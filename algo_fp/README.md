# Фінальний проєкт: алгоритми та структури даних

Репозиторій містить розв'язки сімох завдань фінального проєкту. Кожне
завдання — окрема тека `task_N/` із самостійним `main.py`.

## Завдання 1. Однозв'язний список

Файл: [task_1/main.py](task_1/main.py)

Реалізовано клас `LinkedList` із трьома ключовими операціями:

- `reverse(linked_list)` — реверсує список ітеративно, перепризначаючи
  `next`-посилання `O(n)` за часом і `O(1)` за пам'яттю;
- `merge_sort(linked_list)` — сортування злиттям, адаптоване для
  однозв'язного списку (поділ через slow/fast-вказівники, злиття на місці);
- `merge_sorted_lists(a, b)` — об'єднує два вже відсортовані списки в один
  без створення нових вузлів.

Перевірка: вихідний `[3,1,4,1,5,9,2,6,5,3,5]` → реверс
`[5,3,5,6,2,9,5,1,4,1,3]` → сортування `[1,1,2,3,3,4,5,5,5,6,9]`.

## Завдання 3. Алгоритм Дейкстри на бінарній купі

Файл: [task_3/main.py](task_3/main.py)

`dijkstra(graph, start)` повертає словники найкоротших відстаней і
попередників для відновлення шляху. Граф — словник суміжності з вагами.
Пріоритетна черга — `heapq` (мін-купа), що дає складність
`O((V + E) log V)`. Виконується перевірка `current_dist > distances[current]`,
щоб ігнорувати застарілі записи в купі.

## Завдання 4. Візуалізація бінарної купи

## Завдання 5. Візуалізація обходів дерева

Файл: [task_5/main.py](task_5/main.py)

- `dfs_iterative(root)` — обхід у глибину через **стек** (`list.pop()`).
- `bfs_iterative(root)` — обхід у ширину через **чергу**
  (`collections.deque.popleft()`).

Рекурсія не використовується. Кожному вузлу при відвідуванні присвоюється
колір з градієнта від темно-синього `#1255A0` до світло-блакитного
`#C8E0FF`. Результати — `task_5/dfs_traversal.png` і
`task_5/bfs_traversal.png`.

## Завдання 6. Жадібний vs ДП у задачі вибору їжі

Файл: [task_6/main.py](task_6/main.py)

- `greedy_algorithm(items, budget)` — сортує страви за спаданням
  співвідношення `calories / cost` і бере їх, поки вистачає бюджету. Час
  `O(n log n)`, але оптимум не гарантований.
- `dynamic_programming(items, budget)` — класичний 0/1 knapsack за
  таблицею `dp[i][b]`, з відновленням набору страв. Час `O(n · budget)`,
  гарантовано дає оптимальне рішення.

Приклад: бюджет 100 →
жадібний `['cola', 'potato', 'pepsi', 'hot-dog']` = 870 ккал;
ДП `['pizza', 'pepsi', 'cola', 'potato']` = **970 ккал**.
ДП повністю використовує бюджет і отримує на ~11% більше калорій.

## Завдання 7. Метод Монте-Карло для двох кубиків

Файл: [task_7/main.py](task_7/main.py)

`simulate(rolls)` емітує задану кількість кидків двох кубиків, після чого
обчислюються емпіричні ймовірності для кожної суми (2…12). Будується
таблиця та порівняльний графік `task_7/dice_probabilities.png`.

### Висновки щодо Завдання 7

1. **Збіжність до аналітичних значень.** При мільйоні кидків максимальна
   абсолютна різниця між симуляцією та аналітичним розподілом склала менш
   ніж **0.05 процентного пункту**, а відносна — менше **0.4%**. Це
   підтверджує коректність як симуляції, так і самого методу Монте-Карло.
2. **Швидкість збіжності.** Похибка методу Монте-Карло зменшується як
   `O(1/√n)`. Тобто щоб зменшити похибку на порядок, потрібно у 100 разів
   більше випробувань. На `n = 10⁶` точність вже така, що похибка
   статистично порівнянна з аналітикою.
3. **Симетрія розподілу.** Емпіричні дані відтворюють очікувану
   симетричність відносно суми `7`: значення для пар `(2, 12)`, `(3, 11)`,
   `(4, 10)`, `(5, 9)`, `(6, 8)` дуже близькі. Це додаткова валідація
   реалізації.
4. **Коли застосовувати Монте-Карло.** Для простої задачі з двома кубиками
   аналітичне рішення тривіальне (`6/36`, `5/36` тощо), тому метод
   Монте-Карло тут — навчальний приклад. Його справжня цінність
   проявляється у задачах, де аналітичне обчислення складне або
   неможливе: багатовимірні інтеграли, складні стохастичні системи,
   фінансові моделі, фізичні симуляції тощо.
